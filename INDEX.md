# INDEX.md — repository map

Referat is a personal, fully offline meeting recorder for one Windows 11
laptop. A system tray app captures the microphone and the system audio output
as two separate WAV streams, then transcribes them with `faster-whisper` and
diarizes the loopback channel with `pyannote.audio`, producing one
chronological, timestamped, speaker-labeled `transcript.md` per meeting in the
configured meetings folder. Speakers it recognises from earlier meetings are
labeled by name; the rest wait for `referat label`, which plays their voice,
asks who it was, and remembers the answer. A small `referat` CLI lists
meetings, re-runs transcription, names those speakers, says who it knows a name
for and where they appear, reports what the
tray app is doing, regenerates the meetings folder's own `INDEX.md`
dashboard, prints the hotwords Whisper is told about before it transcribes,
and maintains the projects a meeting is tagged with. The folder itself carries a small scaffold: a `/cleanup` slash
command that writes `notes.md` beside a transcript when asked, and the
permission rule that keeps that pass out of the voiceprints. The primary UI is a
**command center**: a PySide6 desktop window the tray app owns and opens from the
tray icon, built on three entities — meetings, projects and people — with an
untagged inbox, a transcript beside its notes, and a page per person unifying a
voiceprint identity with the projects and meetings they appear in. All three
entities are built, one tab each, behind a **dashboard** that is what the window
opens on — recent meetings and the three queues of work still owed, untagged
meetings, speakers nobody has named and meetings with no notes yet, every row a
link to the meeting rather than a button that acts. Then the meetings list, the transcript-and-notes
viewer with timestamp cross-links, recording buttons onto the same methods the
hotkeys call, a tray icon Qt now owns, an untagged inbox with a tag picker that
also creates projects, a labeling dialog, a projects page carrying the glossaries
and the merged hotword list, and a people page a name in any document links to.
A VS Code extension was the primary UI from step 15 until then — a sidebar of
meetings carrying their tags and their lifecycle, the buttons that write notes,
re-transcribe, tag and name speakers, and a status bar item saying what the tray
is doing — and was **deleted at step 23**, once the window grew the last two
things it could do and the window could not: re-transcribing a meeting, and
promoting a staged one out of staging with its audio released. A project is a label a
meeting carries zero or more of, kept in the meetings folder's own
`projects.json`, and a meeting's lifecycle is one explicit field that every
surface renders rather than infers. Since **build step 13** a project may also
carry Google Docs, and `referat project sync` writes every meeting tagged with it
into each of them as a dated block found by its own `[referat:<id>]` anchor —
reconciliation rather than appending, so a note rewritten by `/cleanup` is
re-rendered in place and a meeting that lost the tag is reported rather than
quietly removed. That is the first thing Referat has ever sent anywhere, and what
it sends is `notes.md` and nothing else: never the transcript, never the audio,
never a voiceprint.
This file maps every source file
in the repository; keep it current whenever files are added, removed, or
repurposed.

| [referat/__init__.py](referat/__init__.py)             | Package docstring and `__version__`.                                   |
| [referat/build_info.py](referat/build_info.py)         | Which code is actually running: the newest mtime across the package's modules, sampled once at import, plus when the process started. There is no build to date — Referat is installed editable, so the `.py` files *are* the program — and the sampling is at import on purpose, since a timestamp read later would describe the code on disk rather than the code loaded. Sampled with `rglob` and not `glob`, which is a correction: it saw only `referat/*.py` and so missed the whole of `referat/ui/` — a third of the package and the part that changes most — so a tray running an hour-old window reported itself current, and during the 2026-09-03 crash hunt that stamp was the evidence that nearly exonerated the code that was actually crashing. The tray menu shows both; `outdated()` compares a tray's recorded value against a fresh read, which only a second process can do, and `referat status` is where that happens. Second-resolution, because `status.json` stores the value that way and a finer one made every fresh tray report itself out of date. |
| [referat/config.py](referat/config.py)                 | Frozen dataclasses mirroring `config.toml`, `tomllib` loading with unknown-key warnings, validation, first-run bootstrap of the config file and of the meetings folder scaffold, Hugging Face token lookup, and the resolvers `voices_dir()`, `staging_dir()` and `meeting_roots()` — the one answer each to where the voiceprints live, where recording happens, and where a meeting may be found. `[transcription].languages` is one key with three meanings — one code pins a language, two or more detect per channel and take the best of those, `[]` is bare autodetect — and it is shape-checked here and never checked for membership, because faster-whisper lives behind the `transcribe` extra and `referat config` runs in the base install. `[cleanup].claude_binary` is where the `claude` binary is when it cannot be found on its own — an escape hatch and **not a credential**, since `claude` owns all authentication and no API key belongs in this file. `[paths].google_client_secret_file` and `google_token_file` are build step 13's two, and the difference between them is worth keeping: the first is the OAuth *client* downloaded from the console and describes the application, while the second is the cached refresh token and is a credential of yours — deleting it is how you sign out. Both are resolved through methods on `Config` rather than read off the dataclass, because `_coerce` expands `~` only on a value that came out of the TOML and a key left commented out would reach a caller as a literal tilde. `[bleed]` is a deliberate exception to the no-knobs-nobody-asked-for rule, on the same grounds `[speakers]`' thresholds were: it is the only place a rule deletes lines from a transcript, and `min_tokens` is refused below 3 rather than merely warned about, because it is the knob whose wrong value is most destructive. |

Also `actions.json` and the generated `days/` folder, both excluded by name from `list_meeting_dirs` even though neither could pass its `meta.json` gate — a rule belongs where somebody would break it. `write_text_atomic` retries its `os.replace` briefly: the meetings folder is inside Dropbox, a sync client holds a file it is uploading without sharing delete access, and the rename then fails with `WinError 5` at random on whatever was being written. Transient, so retried rather than reported; the atomicity is untouched, since it is the rename that is re-attempted. |
| [referat/logging_setup.py](referat/logging_setup.py)   | Rotating file log in the state dir, plus a console handler when stderr exists (absent under `pythonw.exe`). `CHATTY` raises six libraries to WARNING — `httpx` above all, whose one `GET .../revision/main` per model load reads exactly like a 3 GB download beginning and is a metadata check against a model already cached on disk. Raised rather than silenced, so a real failure still says so. |
| [referat/cli.py](referat/cli.py)                       | The `referat` command line entry point: `--version`, `config`, `list`, `show`, `transcript`, `status`, `devices`, `rerun`, `promote`, `reflow`, `relabel`, `debleed`, `delete`, `label`, `index`, `hotwords [--json]`, `people [--json]`, `notes`, `project add [--json]|rename|describe|glossary|archive|unarchive|rm|link-doc|unlink-doc|sync|list [--json]`, `tag`, `untag`, `state`, `actions`, `day` and `notes`, plus the table renderer. `people` is everybody there is a name for, with how many voiceprints are filed under it, the meetings those came out of, the meetings the name appears in and the projects those carry — the two counts differing being the point, since recognition files nothing new. It prints **names, counts and meeting ids and nothing else**: no embedding and no path into `.voices/` reaches `people_document`, which is the rule a listing verb about biometric data is easiest to break. It also names any name a transcript still uses that the database holds nothing under, which nothing else compares. `hotwords` prints the merged list with the source of each term and names what the 224-token cap dropped — a cap nobody can see is how this becomes a bug report about one specific name that is never heard right. `promote --release-audio` is the off-ramp for a meeting the quality gate stranded in staging: it deletes the WAVs through `transcribe.release_audio`, calls the transcript accepted by writing `transcribed`, and then promotes — and without the flag it refuses and names the files, which is the whole safety of the bare form. `project add --json` emits the project it just created, because an id is `slugify` plus a collision suffix and a caller matching the name back out of `project list` gets the wrong project whenever two share one. `relabel` spells the owner's name into transcripts written while the pipeline still rendered them `ME`, and only for a meeting whose microphone clustered into nothing but the owner — anywhere else `ME` may be somebody else in the room. `debleed` is the third repair after `reflow` and `relabel` and the only one that deletes whole entries: it collapses the lines a hybrid meeting recorded twice, gated on a name resolving to clusters on *both* channels — the one piece of provenance a rendered transcript keeps — keeping whichever copy contains the other, never the better-punctuated one, which was measured to be a coin flip. Dry by default; `--apply` records every removed line under `transcription.debleed` *before* touching the transcript, so a deletion stays readable and reversible, which is what keeps it on the right side of the immutability rule. `delete` removes a meeting folder, refusing while it is recording or transcribing, and says in its confirmation that a deletion inside a synced folder is not one and that the voiceprints stay. Every mutation of the projects file, of a meeting's tags and of its lifecycle happens here and nowhere else; `project` takes a second positional verb inside the one argparse block rather than growing a dispatcher of its own. `devices` lists the input and loopback devices and marks the ones `[audio]` resolves to, asking `recorder`'s own resolvers rather than copying their rules. Dispatch only for the three heavy commands, which are imported inside the branch that runs them. `apply_tags` is the only implementation of changing a meeting's tags — `tag` and `untag` are it in one direction each, the command center's picker is it in both, and it opens `projects.json` only when something is being *added*, because guarding a removal on that file would make a broken one the single thing that pins an orphan to a meeting forever. It answers with an `Outcome` whose message is unprefixed, the callers supplying `referat tag:` or `referat untag:` or, in a dialog, nothing — the same reason `resolve_meeting` returns its complaint rather than printing it. `create_project` hands back the `Project` itself, so no caller ever guesses an id, and `rename_project`, `set_description`, `set_glossary` and `remove_project` are the same arrangement for the other four mutations — one guarded function each, which the verb and the command center's projects page both call rather than reaching into `ProjectsDB`. `project describe` and `project glossary` are the verbs step 20's phase 4 needed before its page could exist, `--add`/`--remove` being ergonomics over a whole-list replacement rather than a second kind of write. `hotwords_document` splits the merged list out of `run_hotwords` and gives it the `--json` step 12b withheld on the recorded ground that nothing read it — which the projects page is what stops being true. `list --json` and `status --json` were written for the deleted VS Code extension and are what the window is built on now, from the same helpers the tables are — `status --json`'s `elapsed` is `format_duration`'s output, so the status bar formats nothing itself; `_label_complaint` rejects the combinations of `label`'s four non-interactive flags that do not mean anything. `show` is one meeting's whole record — `meta.json` through `Meeting.to_json`, wrapped in the four derived answers every surface asks Python for — and its point is the `transcription` block nothing had ever printed, each cluster's match score *and its runner-up, recorded even where the match was refused*, which is the only material for calibrating `[speakers]`' two thresholds. `transcript` reads `transcript.md` back through the parser that lives beside the renderer that wrote it — its `--json` naming which of the labels are *people*, from `voices.name_complaint`, so the command center can link a name without a second copy of the rule that `ME`, `REMOTE` and `SPEAKER_NN` are not one, and carrying `markdown` — the file itself, already read, which is what a copy out of the transcript pane hands over rather than the window opening `transcript.md` for itself — and its table is who spoke, how often and what share of the words — not the transcript itself, which is a file you can already open and the one most likely to hold a character this console cannot encode. `write_notes` and `delete_meeting` are the seventh and eighth guarded functions, split out when the command center grew the two buttons the sidebar had and it did not, and `promote_meeting` is the **ninth**, split out at step 23 for the last of them — one function taking `release_audio` as a direction rather than two, the bare form being the same operation with the deletion refused; `promote_warning` beside it is `delete_warning`'s counterpart, the one text the prompt's refusal and the window's modal both speak in, and it says what deleting a whole meeting does not have to: the transcript survives and the only material it could be re-derived from does not; `delete_warning` is the one text the prompt and the modal both warn with, said once so an irreversible act cannot be described two ways, and `set_notes_written` came out of `run_state` for the same reason. `pending` is phase 6's, and is the one function here that is pure over a *document* rather than over the folder: the three queues the dashboard is made of — untagged, speakers nobody has named, no notes yet — derived from a `list_document` the caller already holds, opening no file. `LIVE` is the pair of statuses it holds out of all three, because a meeting still being recorded or transcribed is not pending work but a wait, which is the same distinction `run_list`'s footer makes when it refuses to suggest a `rerun` for one. *Notes for all…* had its own inline copy of the notes predicate and asks this instead; a queue counted by one rule and drained by another would look right while being wrong. Installs a SIGINT logger in `main` that records when a Ctrl+C *arrived* rather than only where it surfaced: Windows delivers the event to every process on the console and Python can only raise it at a bytecode boundary, so a long call into C hides the delay entirely. Build step 21 added `set_archived` — the sixth guarded project function, and **one function taking a direction rather than two**, which is what `apply_tags` and `set_action_done` already are. Both no-ops come back `ok` having written nothing, and the already-archived message names the date, because that is what tells a no-op from a write at a prompt. `project_names` grew to `(names, archived, complaint)`; `people_document` gained `archived` and a per-person `inactive` off one loader; `project_document` needed nothing at all, since it spreads `to_json`. Build step 13 added the tenth, eleventh and twelfth guarded functions — `link_doc`, `unlink_doc` and `sync_project` — which are the only three verbs in this file that are not a JSON read and a JSON write, and the only ones that open a socket. Each asks `gdocs.available()` **first**, before `projects.json` is opened, because a complaint about an unknown project id is advice about the wrong problem when the thing that would do the work is not installed. `link_doc` asks no questions: the create-or-select choice is `run_project_link_doc`'s, at a prompt, for the same reason `name_speaker` never calls `input()`. `sync_project` writes `meta.json` as each block lands rather than once at the end, so an interrupted sync resumes instead of re-rendering a document that is already right, and it stops a document on the first failure rather than carrying on against indices that may have moved. `project_document` gained `pending` — how many of a project's meetings are behind at least one of its docs — which is entirely local, so `project list` stays a JSON read, and a `PENDING` column beside `DOCS` that is blank rather than `0` for a project with no docs: there is nowhere for it to be behind, which is a different thing from being current. |

Written on every transition, read by `referat status`, and `is_running` asks Windows whether that pid is still there. |
| [referat/hotkeys.py](referat/hotkeys.py)               | Registers the two configured global combos through `keyboard`, debounced against auto-repeat from a held USB button. |
| [referat/tray.py](referat/tray.py)                     | The **recorder core** and the process entry point, and since step 20 it imports no toolkit at all: the state machine, the hotkey wiring, the sleep hold, the single-instance mutex, `status.json`, the recorder it starts and stops, and the background transcription job. `on_toggle_record` is split into `start_meeting` and `stop_meeting` so the command center's three buttons and the one record hotkey share one path into the state machine. Step 23 added `rerun_meeting` and `_queue_transcription` for the same reason one layer down: a meeting just stopped, a meeting the last process did not finish and a meeting somebody asked to re-transcribe are the same three lines — count the job, claim the state, start the thread — and were three copies of them. A rerun runs *here* rather than in a `cli` function because what it costs is the state machine, the job count and a thread, none of which a window may touch; the rules are `rerun.check`'s. `App.notify` is the whole seam to the UI — the Qt shell replaces it with a balloon, and it logs when nothing has. `main` starts this core *before* importing `referat.ui.shell`, which is what makes step 20's ordering rule a fact about four lines rather than an intention. At startup it reconciles meetings left `transcribing` by a process that is gone and re-queues the ones that still have audio, so a lid closed mid-job costs a delay rather than a chore. |
| [referat/meeting.py](referat/meeting.py)               | The meeting record and `meta.json` read/write: the explicit lifecycle `MeetingStatus` every surface renders, the pure map from the legacy `stopped`/`done` values onto it, the project ids in `tags`, pause intervals, per-channel audio info, the duration formatter `referat list` and the meetings dashboard share, folder creation in the staging folder through `paths.new_meeting_dir`, `resolve_meeting` for the commands that take an id, and `load_meetings` across both roots. Carries `missing_channels`, the written record of a channel that never opened — absent from `audio` was the old way of knowing and nobody ever looked. `reconcile_interrupted` clamps a meeting left `transcribing` by a process that is gone back to `recorded` — the residue a hard kill leaves, which no in-process handler can promise to clean up and which blocks the very `rerun` that would repair it. |
| [referat/projects.py](referat/projects.py)             | `<meetings_dir>/projects.json`: one entry per project with an id, a display name, its Google Docs, its `glossary` and a one-line description, plus the slug rule, the project-name validator, `clean_terms` — the whitespace-collapsing, case-insensitive deduplication a glossary goes through on the way into the file, so what `referat project glossary` prints is what `referat hotwords` will merge — and the tag list functions `referat tag` and `untag` write with. The mutations here are primitives that change one field and save nothing; what makes a change correct — the unreadable-file guard, the name rules, the unknown-id refusal and the single save — is `cli.py`'s, and every surface goes through it. A project is a label a meeting carries, not a container it sits in, and the id is fixed at creation so a rename touches this file alone. Never raises on a read — the hotword merge will call it from inside the pipeline — and refuses to be *written* after a failed parse, which would replace every project with an empty list. Build step 21 added **`archived_at`**: a project can be *finished* as well as deleted, and archiving hides it from the tag picker and changes nothing else — the entry stays, the tags stay, they still resolve, and the glossary still feeds the hotword list. A timestamp rather than a flag because `""` is already this file's falsy absence, and a second archive does not move the date. **`archived_ids()` is beside `name_map()` and never inside it**: that map is the orphan oracle, so narrowing it would render every archived project's tags as orphans everywhere at once. |
| [referat/actions.py](referat/actions.py)               | The `## Action items` section of every `notes.md`, parsed, and the sidecar recording what has been done about it. Parsed and never re-extracted: `/cleanup` already decided what an action item is, and an audit over the whole corpus found 64 items with no deviations from `- **owner(s)** — text`, which is what makes this a parse rather than a guess. An item's **identity is its wording** — a hash of the note's own sentence and never of a correction typed over it — so an edit is stable and revertible, a re-cleanup that merely re-wraps a bullet keeps its key, and one that genuinely re-words it orphans the tick, which is kept and shown rather than pruned. The due date comes from a **cue clause** and never from any bare date in the sentence: the simpler rule got five of sixty-four wrong and every one of them in the direction that matters, showing a meeting date or a start date as a deadline. Nothing here writes `notes.md`; the note is the record of what the meeting produced, and ticking, correcting and dropping are facts about the reader. `ActionsDB` mirrors `ProjectsDB` down to the `unreadable` flag — no state for reading, a refusal for writing — and its mutators are primitives that save nothing, with the operations in `cli.py`. Light on purpose: stdlib only, so no `numpy` stands behind `referat actions`. |
| [referat/power.py](referat/power.py)                   | The sleep hold: `SetThreadExecutionState(ES_CONTINUOUS \| ES_SYSTEM_REQUIRED)` owned by a single keeper thread, because the flags are per-thread while Referat's transitions arrive on several. Keyed by *reason* since 2026-09-03 — the recorder holds one while capturing and the notes queue another while `claude` runs, and a single boolean let whichever finished first drop the hold out from under the other. Held for every state but idle, transcription included: this file used to say a job was "no reason to keep the laptop awake", until a meeting idled into Modern Standby mid-diarization. Also `SuspendWatcher`, which cannot prevent a suspend — closing the lid is a power-plan action no process can veto — but detects one from the wall clock and writes down how much time was lost and what was in flight, so a log that simply stops stops being ambiguous. |
| [referat/gpu.py](referat/gpu.py)                       | One function, `release`, handing torch's CUDA arena back to the driver after a job and logging how much came back. `del model` returns the Python reference and not the memory: torch's caching allocator keeps every block it has taken, so an idle tray sat on 8.4 GB of a 12 GB card and the next process to want a model stalled inside CTranslate2. Never raises, a no-op when CUDA was never initialized, and honest in its docstring about the two things it cannot reclaim — CTranslate2's own allocator and the CUDA context. Its `gc.collect()` runs on the **main thread only**: a collect destroys what it reaps on the calling thread, PySide6 widgets included, and the tray calls this from a transcription thread — the same wrong-thread hazard that crashed the tray through `Shell.notify`. Whether that skip is what stranded 5205 MiB in an idle tray on 2026-09-03 is unproven and recorded as open — the retention does not reproduce outside the tray; `transcribe.unload_model` is the fix that does not depend on the answer. |
| [referat/progress.py](referat/progress.py)             | What the slow things are doing right now, for whatever wants to show it. A registry of running jobs — a key, a title, a phase and a fraction — with listeners, and the same shape as `App.notify`: the work reports, and something else decides whether anybody is looking. Imports no toolkit, is never required (a job that never calls `begin` does not appear, so `referat rerun` is unchanged at a prompt), and never lets a listener raise into the pipeline. Live state and not history — a finished job is removed, because what happened is the log's business. The only true fraction in Referat is faster-whisper's `segment.end`; everything else reports a phase and `None`, which is the honest absence of a claim where zero percent would be one. |
| [referat/notes.py](referat/notes.py)                   | Writing `notes.md`, by spawning the official `claude` binary with `/cleanup` in the **meetings folder** — never the repository, because the prompt, that folder's `CLAUDE.md` and the `.voices/` deny rule all live in its `.claude/`. `Read,Write,Glob` and never `Bash`. Referat summarises nothing itself and touches no credential: `claude` owns all authentication and no Anthropic SDK is a dependency. Finding the binary is the awkward half — it is not on `PATH` and ships inside the Claude Code VS Code extension under a version that changes weekly, so this reads that folder and **honours the `.obsolete` file VS Code writes beside it**, then falls back to `PATH`. Resolved at spawn time and never persisted, or the stored path outlives the directory. Runs with `--output-format stream-json --verbose` and turns each event into a phase — *reading transcript.md*, *writing notes.md* — because plain `-p` prints one blob when it is over and the progress line read "starting claude" for two silent minutes; the verdict comes from the final `result` event, which carries `is_error`, and not from the exit code alone. Since the day summary arrived it is two prompts over one `_spawn`: `/cleanup` for a meeting and `/standup` for a day, sharing the cwd, the three allowed tools and the streamed events because all of that is a property of running Claude Code in that folder rather than of what is being written. ## Deleted — the VS Code extension

`referat-vscode/` was the primary UI from build step 15 to step 20 and was
**deleted at step 23**, along with `.vscode/launch.json` and `.vscode/tasks.json`,
which existed only to run it from source under F5. It went once the command
center could re-transcribe a meeting and promote a staged one out of staging —
the last two things the sidebar could do and the window could not — because the
whole argument for keeping it was parity, and the whole cost of keeping it was
two implementations of one UI.

It is listed here rather than merely removed because the map is also a record of
what this repository has held. Three things it taught outlived it and are cited
in the modules that carry them: **build every node with `textContent`**, which is
`referat/ui/viewer.py`'s escaping rule; **a picker diffs against what the meeting
carries and never against the set it mutates**, which is
`referat/ui/tags.py`'s two sets; and **a refusal reaches the user in the words of
whatever owns the rule**, which its `mutate` did by reading the CLI's stderr and
which `cli.Outcome` now does in process. The `--json` documents it was the first
reader of all stay: they are the shape a surface and the CLI agree on, and a
document you can print is a document you can test.
