# INDEX.md — repository map

Referat is a personal, fully offline meeting recorder for one Windows 11
laptop. A system tray app captures the microphone and the system audio output
as two separate WAV streams, then transcribes them with `faster-whisper` and
diarizes the loopback channel with `pyannote.audio`, producing one
chronological, timestamped, speaker-labeled `transcript.md` per meeting in the
configured meetings folder. Speakers it recognises from earlier meetings are
labeled by name; the rest wait for `referat label`, which plays their voice,
asks who it was, and remembers the answer. A small `referat` CLI lists
meetings, re-runs transcription, names those speakers, says who it knows a name
for and where they appear, reports what the
tray app is doing, regenerates the meetings folder's own `INDEX.md`
dashboard, prints the hotwords Whisper is told about before it transcribes,
and maintains the projects a meeting is tagged with. The folder itself carries a small scaffold: a `/cleanup` slash
command that writes `notes.md` beside a transcript when asked, and the
permission rule that keeps that pass out of the voiceprints. The primary UI is a
**command center**: a PySide6 desktop window the tray app owns and opens from the
tray icon, built on three entities — meetings, projects and people — with an
untagged inbox, a transcript beside its notes, and a page per person unifying a
voiceprint identity with the projects and meetings they appear in. All three
entities are built, one tab each, behind a **dashboard** that is what the window
opens on — recent meetings and the three queues of work still owed, untagged
meetings, speakers nobody has named and meetings with no notes yet, every row a
link to the meeting rather than a button that acts. Then the meetings list, the transcript-and-notes
viewer with timestamp cross-links, recording buttons onto the same methods the
hotkeys call, a tray icon Qt now owns, an untagged inbox with a tag picker that
also creates projects, a labeling dialog, a projects page carrying the glossaries
and the merged hotword list, and a people page a name in any document links to.
A VS Code extension was the primary UI from step 15
until then
— a sidebar of meetings carrying their tags and their lifecycle, the buttons that
write notes, re-transcribe, tag and name speakers, and a status bar item saying
what the tray is doing — and is now in maintenance, fixed when it breaks and
deleted once the command center reaches parity with it. A project is a label a
meeting carries zero or more of, kept in the meetings folder's own
`projects.json`, and a meeting's lifecycle is one explicit field that every
surface renders rather than infers. Later steps let the
tray tag a meeting as it stops, and push the notes of a tagged meeting into each
of its projects' Google Docs.
This file maps every source file
in the repository; keep it current whenever files are added, removed, or
repurposed.

## Package — [referat/](referat/)

| File                                                  | Description                                                            |

| [referat/__init__.py](referat/__init__.py)             | Package docstring and `__version__`.                                   |
| [referat/build_info.py](referat/build_info.py)         | Which code is actually running: the newest mtime across the package's modules, sampled once at import, plus when the process started. There is no build to date — Referat is installed editable, so the `.py` files *are* the program — and the sampling is at import on purpose, since a timestamp read later would describe the code on disk rather than the code loaded. Sampled with `rglob` and not `glob`, which is a correction: it saw only `referat/*.py` and so missed the whole of `referat/ui/` — a third of the package and the part that changes most — so a tray running an hour-old window reported itself current, and during the 2026-09-03 crash hunt that stamp was the evidence that nearly exonerated the code that was actually crashing. The tray menu shows both; `outdated()` compares a tray's recorded value against a fresh read, which only a second process can do, and `referat status` is where that happens. Second-resolution, because `status.json` stores the value that way and a finer one made every fresh tray report itself out of date. |
| [referat/config.py](referat/config.py)                 | Frozen dataclasses mirroring `config.toml`, `tomllib` loading with unknown-key warnings, validation, first-run bootstrap of the config file and of the meetings folder scaffold, Hugging Face token lookup, and the resolvers `voices_dir()`, `staging_dir()` and `meeting_roots()` — the one answer each to where the voiceprints live, where recording happens, and where a meeting may be found. `[cleanup].claude_binary` is where the `claude` binary is when it cannot be found on its own — an escape hatch and **not a credential**, since `claude` owns all authentication and no API key belongs in this file. `[bleed]` is a deliberate exception to the no-knobs-nobody-asked-for rule, on the same grounds `[speakers]`' thresholds were: it is the only place a rule deletes lines from a transcript, and `min_tokens` is refused below 3 rather than merely warned about, because it is the knob whose wrong value is most destructive. |

| [referat/logging_setup.py](referat/logging_setup.py)   | Rotating file log in the state dir, plus a console handler when stderr exists (absent under `pythonw.exe`). `CHATTY` raises six libraries to WARNING — `httpx` above all, whose one `GET .../revision/main` per model load reads exactly like a 3 GB download beginning and is a metadata check against a model already cached on disk. | [referat/cli.py](referat/cli.py)                       | The `referat` command line entry point: `--version`, `config`, `list`, `show`, `transcript`, `status`, `devices`, `rerun`, `promote`, `reflow`, `relabel`, `debleed`, `delete`, `label`, `index`, `hotwords [--json]`, `people [--json]`, `notes`, `project add [--json]|rename|describe|glossary|rm|list [--json]`, `tag`, `untag` and `state`, plus the table renderer. `people` is everybody there is a name for, with how many voiceprints are filed under it, the meetings those came out of, the meetings the name appears in and the projects those carry — the two counts differing being the point, since recognition files nothing new. It prints **names, counts and meeting ids and nothing else**: no embedding and no path into `.voices/` reaches `people_document`, which is the rule a listing verb about biometric data is easiest to break. It also names any name a transcript still uses that the database holds nothing under, which nothing else compares. `hotwords` prints the merged list with the source of each term and names what the 224-token cap dropped — a cap nobody can see is how this becomes a bug report about one specific name that is never heard right. `promote --release-audio` is the off-ramp for a meeting the quality gate stranded in staging: it deletes the WAVs through `transcribe.release_audio`, calls the transcript accepted by writing `transcribed`, and then promotes — and without the flag it refuses and names the files, which is the whole safety of the bare form. `project add --json` emits the project it just created, because an id is `slugify` plus a collision suffix and a caller matching the name back out of `project list` gets the wrong project whenever two share one. `relabel` spells the owner's name into transcripts written while the pipeline still rendered them `ME`, and only for a meeting whose microphone clustered into nothing but the owner — anywhere else `ME` may be somebody else in the room. `debleed` is the third repair after `reflow` and `relabel` and the only one that deletes whole entries: it collapses the lines a hybrid meeting recorded twice, gated on a name resolving to clusters on *both* channels — the one piece of provenance a rendered transcript keeps — keeping whichever copy contains the other, never the better-punctuated one, which was measured to be a coin flip. Dry by default; `--apply` records every removed line under `transcription.debleed` *before* touching the transcript, so a deletion stays readable and reversible, which is what keeps it on the right side of the immutability rule. `delete` removes a meeting folder, refusing while it is recording or transcribing, and says in its confirmation that a deletion inside a synced folder is not one and that the voiceprints stay. Every mutation of the projects file, of a meeting's tags and of its lifecycle happens here and nowhere else; `project` takes a second positional verb inside the one argparse block rather than growing a dispatcher of its own. `devices` lists the input and loopback devices and marks the ones `[audio]` resolves to, asking `recorder`'s own resolvers rather than copying their rules. Dispatch only for the three heavy commands, which are imported inside the branch that runs them. `apply_tags` is the only implementation of changing a meeting's tags — `tag` and `untag` are it in one direction each, the command center's picker is it in both, and it opens `projects.json` only when something is being *added*, because guarding a removal on that file would make a broken one the single thing that pins an orphan to a meeting forever. It answers with an `Outcome` whose message is unprefixed, the callers supplying `referat tag:` or `referat untag:` or, in a dialog, nothing — the same reason `resolve_meeting` returns its complaint rather than printing it. `create_project` hands back the `Project` itself, so no caller ever guesses an id, and `rename_project`, `set_description`, `set_glossary` and `remove_project` are the same arrangement for the other four mutations — one guarded function each, which the verb and the command center's projects page both call rather than reaching into `ProjectsDB`. `project describe` and `project glossary` are the verbs step 20's phase 4 needed before its page could exist, `--add`/`--remove` being ergonomics over a whole-list replacement rather than a second kind of write. `hotwords_document` splits the merged list out of `run_hotwords` and gives it the `--json` step 12b withheld on the recorded ground that nothing read it — which the projects page is what stops being true. `list --json` and `status --json` are the documents the VS Code extension reads, built from the same helpers the tables are — `status --json`'s `elapsed` is `format_duration`'s output, so the status bar formats nothing itself; `_label_complaint` rejects the combinations of `label`'s four non-interactive flags that do not mean anything. `show` is one meeting's whole record — `meta.json` through `Meeting.to_json`, wrapped in the four derived answers every surface asks Python for — and its point is the `transcription` block nothing had ever printed, each cluster's match score *and its runner-up, recorded even where the match was refused*, which is the only material for calibrating `[speakers]`' two thresholds. `transcript` reads `transcript.md` back through the parser that lives beside the renderer that wrote it — its `--json` naming which of the labels are *people*, from `voices.name_complaint`, so the command center can link a name without a second copy of the rule that `ME`, `REMOTE` and `SPEAKER_NN` are not one — and its table is who spoke, how often and what share of the words — not the transcript itself, which is a file you can already open and the one most likely to hold a character this console cannot encode. `write_notes` and `delete_meeting` are the seventh and eighth guarded functions, split out when the command center grew the two buttons the sidebar had and it did not; `delete_warning` is the one text the prompt and the modal both warn with, said once so an irreversible act cannot be described two ways, and `set_notes_written` came out of `run_state` for the same reason. `pending` is phase 6's, and is the one function here that is pure over a *document* rather than over the folder: the three queues the dashboard is made of — untagged, speakers nobody has named, no notes yet — derived from a `list_document` the caller already holds, opening no file. `LIVE` is the pair of statuses it holds out of all three, because a meeting still being recorded or transcribed is not pending work but a wait, which is the same distinction `run_list`'s footer makes when it refuses to suggest a `rerun` for one. *Notes for all…* had its own inline copy of the notes predicate and asks this instead; a queue counted by one rule and drained by another would look right while being wrong. Installs a SIGINT logger in `main` that records when a Ctrl+C *arrived* rather than only where it surfaced: Windows delivers the event to every process on the console and Python can only raise it at a bytecode boundary, so a long call into C hides the delay entirely. |

| [referat/gpu.py](referat/gpu.py)                       | One function, `release`, handing torch's CUDA arena back to the driver after a job and logging how much came back. `del model` returns the Python reference and not the memory: torch's caching allocator keeps every block it has taken, so an idle tray sat on 8.4 GB of a 12 GB card and the next process to want a model stalled inside CTranslate2. Never raises, a no-op when CUDA was never initialized, and honest in its docstring about the two things it cannot reclaim — CTranslate2's own allocator and the CUDA context. Its `gc.collect()` runs on the **main thread only**: a collect destroys what it reaps on the calling thread, PySide6 widgets included, and the tray calls this from a transcription thread — the same wrong-thread hazard that crashed the tray through `Shell.notify`. |
| [referat/progress.py](referat/progress.py)             | What the slow things are doing right now, for whatever wants to show it. A registry of running jobs — a key, a title, a phase and a fraction — with listeners, and the same shape as `App.notify`: the work reports, and something else decides whether anybody is looking. Imports no toolkit, is never required (a job that never calls `begin` does not appear, so `referat rerun` is unchanged at a prompt), and never lets a listener raise into the pipeline. Live state and not history — a finished job is removed, because what happened is the log's business. The only true fraction in Referat is faster-whisper's `segment.end`; everything else reports a phase and `None`, which is the honest absence of a claim where zero percent would be one. |
| [referat/notes.py](referat/notes.py)                   | Writing `notes.md`, by spawning the official `claude` binary with `/cleanup` in the **meetings folder** — never the repository, because the prompt, that folder's `CLAUDE.md` and the `.voices/` deny rule all live in its `.claude/`. `Read,Write,Glob` and never `Bash`. Referat summarises nothing itself and touches no credential: `claude` owns all authentication and no Anthropic SDK is a dependency. Finding the binary is the awkward half — it is not on `PATH` and ships inside the Claude Code VS Code extension under a version that changes weekly, so this reads that folder and **honours the `.obsolete` file VS Code writes beside it**, then falls back to `PATH`. Resolved at spawn time and never persisted, or the stored path outlives the directory. Runs with `--output-format stream-json --verbose` and turns each event into a phase — *reading transcript.md*, *writing notes.md* — because plain `-p` prints one blob when it is over and the progress line read "starting claude" for two silent minutes; the verdict comes from the final `result` event, which carries `is_error`, and not from the exit code alone. |
| [referat/recorder.py](referat/recorder.py)             | Dual-stream capture: `sounddevice` mic and WASAPI loopback to two mono WAVs, device selection by config substring — `mic_device_candidates` ranks *every* host API exposing the wanted microphone and ends at the system default, and `_start_mic` walks it, because one device refusing with `-9992` cost a whole meeting while three other routes to the same Jabra sat untried — a recording clock with silence padding, incrementally updated WAV headers, and pause handling. |
| [referat/transcribe.py](referat/transcribe.py)         | `faster-whisper` over both of a meeting's WAVs: chunked decoding and Referat's own numpy polyphase resampler — contract-compatible with the `scipy.signal.resample_poly` it replaced, because Smart App Control blocks scipy's unsigned DLLs at unpredictable moments and nothing between a WAV and a transcript may depend on that — backend selection with a CUDA-to-CPU fallback that a `DecodeError` deliberately skips, the transcript renderer, the parser `referat transcript` and the command center read it back with — kept in this file so the format is described once and the two cannot drift — and the blank line it puts between entries — a single newline is a Markdown soft break, so the old form rendered as one unbroken paragraph, and `reflow_transcript` is the pure function `referat reflow` repairs the older files with — the `transcription` block of `meta.json`, the quality gate that decides whether the audio may be deleted and the `release_audio` that does the deleting — separable since step 15, because `referat promote --release-audio` is a person overruling that gate and `audio_released` has to mean the same thing either way, and split once more into the bare verdict `audio_is_clean` so that `[transcription].keep_audio` can suppress the deletion without costing the verdict: a meeting kept on purpose is not a meeting whose gate failed. Calls out to diarization and then to identification, relabels the segments with whatever names came back, and regenerates the meetings dashboard once the meeting has been promoted. Reports its phases to `referat.progress` — and the segment generator is drained in a loop rather than a comprehension because `segment.end` against the decoded length is the only true progress fraction in the pipeline; `transcribe_meeting` is a `try`/`finally` wrapper around the whole of the work, so an interrupt takes the job off the list rather than leaving a bar that never moves again. Restores the status a meeting arrived with when the run is interrupted rather than raised out of — a `KeyboardInterrupt` is not an `Exception` and used to walk straight past the failure handler, leaving `meta.json` stuck at `transcribing` and its `speaker_names` emptied. |
| [referat/merge.py](referat/merge.py)                   | Interleaving the two channels into one chronological list of `(start, label, text)` entries, with a fixed tie-break so simultaneous speech orders the same way every run. A segment's diarized speaker — a number, or a name, the owner's included — wins over its channel's label here; `ME` and `REMOTE` are what is left when nothing attributed a line. It orders and does not judge: what reaches it has already been through `bleed.apply`. |
| [referat/bleed.py](referat/bleed.py)                   | Dropping the microphone's copy of speech that also arrived on the loopback, which is what a hybrid meeting records when the call comes out of a loudspeaker standing in the room. One-directional by construction: microphone segments may go and loopback segments never do, because a conferencing app does not loop your own capture back into what it plays, so room speech exists only on the microphone and a dropped loopback line could be the far end's only copy. Two rules — a cluster is echo when its speech time sits under loopback speech *and* its text matches loopback text, both, since a room mic is voiced almost continuously; and a per-segment pass for echo that diarization filed under a room person instead. A spared cluster (the owner's, or all of them when the rule convicted the whole channel) is off-limits to both, because a refusal that holds at one level only is undone line by line. Nothing under `[bleed].min_tokens` is ever dropped by text. Pure stdlib, importable without the `transcribe` extra, which is what lets `scripts/bleed_fixture.py` exercise every rule in a second. |
| [referat/diarize.py](referat/diarize.py)               | `pyannote.audio` over **both** channels — the microphone hears the whole room in a meeting held in person: who spoke when, aligned to the transcribed segments by overlap and renumbered `SPEAKER_01`, `SPEAKER_02`, ... across the meeting rather than per channel, so two channels cannot put two people behind one label. Harvests the clustering centroid per speaker and hands back the renaming map so the two stay together. Reports failure rather than raising, so a diarization problem never costs the transcript. Stubs `torchcodec` out before importing pyannote, which imports it eagerly, so Smart App Control has no unsigned DLL to block. |
| [referat/hotwords.py](referat/hotwords.py)             | The one global hotword list handed to faster-whisper before it transcribes: `[transcription].hotword_extras`, every name in the known-voices database and every project's `glossary`, merged in that fixed priority order, deduplicated case-insensitively and capped to Whisper's 224-token prompt window — 223, read out of faster-whisper's own slice rather than inferred. The only correction that acts *before* the transcript exists; everything else here corrects the notes, because the transcript is immutable. Called from `transcribe_channel` rather than from `cli.py`, so the tray and `referat rerun` transcribe against the same list, and it reads both files live so `label --forget` empties a name out of it too. Tokens are estimated rather than counted, so it needs no part of the `transcribe` extra; the estimate errs upwards and was measured against the real large-v3 tokenizer. Never raises — a bad `projects.json` costs hotwords, never a transcript. |
| [referat/voices.py](referat/voices.py)                 | The known-voices database in `<meetings_dir>/.voices/`, or wherever `[paths].voices_dir` puts it: embeddings grouped by name, cosine matching of a diarized cluster against them under a threshold *and* a margin, the snippets cut for whoever is left over, and the owner bootstrap from a meeting whose microphone clustered into exactly one speaker. A lone name in the database is held to the margin on its own score, since there is no runner-up to beat. `Cluster.echo` marks a cluster `bleed` found to be the loopback coming back, and `is_echo` is what keeps it out of `unknown_speakers` and out of `label.apply_name` — the defence belongs where a human is *offered* a cluster, since the pipeline never writes to this database and the two poisoned voiceprints of 2026-09-02 were filed by a person naming a cluster correctly. `VoicesDB.drop` removes the prints one meeting's cluster contributed and refuses to leave anybody with none, which is what `Voiceprint`'s stored provenance was always for. `speaker_channel` and `channel_speakers` answer which file a voice arrived in, which is what the labeling UI shows as a hint and what `referat relabel` gates on. Never raises into the pipeline. Biometric data — never synced, never sent anywhere. |

## VS Code extension — [referat-vscode/](referat-vscode/)

**In maintenance since step 20**, which makes the command center the primary UI:
fixed when it breaks, never extended, not packaged again, and deleted once the
window reaches parity with it. It was the primary UI from step 15 until then, and
the files below are all still live.
**It reimplements nothing**: every meeting it shows comes from `referat list
--json` and every change it makes is a `referat` verb, so the roots, the
formatters, the title rule, the lifecycle vocabulary, the name validators and the
voiceprint writes all stay in Python where they already exist once. That is the
same rule the command center keeps, reached the other way — the window imports
those functions because it is Python already, while this shells out because it is
TypeScript and has no other way in. A sidebar
webview since step 15, replacing step 11's TreeView, and packaged into an
installable `.vsix` at step 12 — nine files, of which one is code. F5 still runs
it from source, which is how it is developed.

The interpreter rather than `uv run`, which Smart App Control blocks here, and rather than `referat.exe`, which Dropbox has deleted twice; `cwd` is what puts the package on `sys.path`. `repoRoot` falls back to the checkout this bundle sits inside (`__dirname/../..`), because F5 loads an extension without opening a folder and the development host otherwise reports the repository missing from a window three directories inside it. |
| [referat-vscode/src/sidebar.ts](referat-vscode/src/sidebar.ts)                     | The Meetings webview view and its watcher, replacing step 11's tree. Sets `webview.html` **once** and thereafter posts documents, because re-rendering on every refresh would collapse an expanded row and stop a snippet mid-playback. Newest first, like the meetings `INDEX.md` and unlike `referat list` — a dashboard is read from the top. Watches both roots for `meta.json`, `notes.md` and `transcript.md`, debounced, because transcription rewrites `meta.json` several times a meeting and every refresh costs a subprocess. Turns snippet paths into webview URIs, which is why the meeting roots have to become `localResourceRoots` once Python has said where they are. |
| [referat-vscode/src/projects.ts](referat-vscode/src/projects.ts)                   | The tag picker and project CRUD, as native QuickPicks — VS Code already has a multi-select with a filter box, and a webview copy would be a worse one. The picker reads `project list --json` fresh rather than trusting the sidebar's cached map, which went stale the moment anything created a project without a refresh following; it diffs the result against **the meeting's own tags**, never against the set it mutates when a project is created inside it, which is what stopped a just-created project from ever being applied; and creating one reopens the picker instead of re-rendering it, because assigning `items` makes VS Code recompute the ticked rows. *Create project “…”* appears as you type. Every path is a shell-out and every refusal is shown in the words the CLI used. |
| [referat-vscode/src/claude.ts](referat-vscode/src/claude.ts)                        | Finding `claude` and running `/cleanup` with it. Not on `PATH` on this machine, so it asks VS Code for the installed Claude Code extension and takes the binary inside it, resolved at spawn time and never cached — that path carries a version and changes with every update. Streams the last non-empty line of its output into the progress toast and the whole of it into the channel. Holds the `--allowedTools "Read,Write,Glob"` constant and the note that `Bash` may never join it. Never touches credentials. |
| [referat-vscode/media/sidebar.css](referat-vscode/media/sidebar.css)                | The sidebar's styling, entirely in VS Code theme variables so it follows the editor's theme. One rule per lifecycle value, and a value nobody styled still prints its own name rather than disappearing. |
| [referat-vscode/media/sidebar.js](referat-vscode/media/sidebar.js)                  | The page: render the posted listing grouped into collapsible sections by project — orphaned tag ids next, untagged last, a two-tag meeting under both — with a search box, keep the expanded rows and the filters across a refresh, remember the folded sections through `vscode.setState`, and post back what was clicked. Every node is built with `textContent` — a meeting title comes out of somebody's `notes.md` and a speaker's line out of a transcript, and neither is markup. Fill the name field from a known-name chip, and disable the button until the host answers so a double click cannot file a voiceprint twice. No matching, no state inference and no duration formatting here. |
