# INDEX.md — repository map

Referat is a personal, fully offline meeting recorder for one Windows 11
laptop. A system tray app captures the microphone and the system audio output
as two separate WAV streams, then transcribes them with `faster-whisper` and
diarizes the loopback channel with `pyannote.audio`, producing one
chronological, timestamped, speaker-labeled `transcript.md` per meeting in the
configured meetings folder. Speakers it recognises from earlier meetings are
labeled by name; the rest wait for `referat label`, which plays their voice,
asks who it was, and remembers the answer. A small `referat` CLI lists
meetings, re-runs transcription, names those speakers, reports what the
tray app is doing, regenerates the meetings folder's own `INDEX.md`
dashboard, and maintains the projects a meeting is tagged with. The folder itself carries a small scaffold: a `/cleanup` slash
command that writes `notes.md` beside a transcript when asked, and the
permission rule that keeps that pass out of the voiceprints. A VS Code extension
is the primary UI over all of it — a sidebar of meetings carrying their tags and
their lifecycle, the buttons that write notes, re-transcribe, tag and name
speakers, and a status bar item saying what the tray is doing — and with the tray
icon it is the only graphical surface this project has. A project is a label a
meeting carries zero or more of, kept in the meetings folder's own
`projects.json`, and a meeting's lifecycle is one explicit field that every
surface renders rather than infers. Later steps package that extension, let the
tray tag a meeting as it stops, and push the notes of a tagged meeting into each
of its projects' Google Docs.
This file maps every source file
in the repository; keep it current whenever files are added, removed, or
repurposed.

| [referat/projects.py](referat/projects.py)             | `<meetings_dir>/projects.json`: one entry per project with an id, a display name, its Google Docs, its `glossary` and a reserved one-line description, plus the slug rule, the project-name validator and the tag list functions `referat tag` and `untag` write with. A project is a label a meeting carries, not a container it sits in, and the id is fixed at creation so a rename touches this file alone. Never raises on a read — the hotword merge will call it from inside the pipeline — and refuses to be *written* after a failed parse, which would replace every project with an empty list. |
| [referat/power.py](referat/power.py)                   | The sleep hold: `SetThreadExecutionState(ES_CONTINUOUS \| ES_SYSTEM_REQUIRED)` owned by a single keeper thread, because the flags are per-thread while Referat's transitions arrive on several. |
| [referat/recorder.py](referat/recorder.py)             | Dual-stream capture: `sounddevice` mic and WASAPI loopback to two mono WAVs, device selection by config substring, a recording clock with silence padding, incrementally updated WAV headers, and pause handling. |
| [referat/transcribe.py](referat/transcribe.py)         | `faster-whisper` over both of a meeting's WAVs: chunked decoding and Referat's own numpy polyphase resampler — contract-compatible with the `scipy.signal.resample_poly` it replaced, because Smart App Control blocks scipy's unsigned DLLs at unpredictable moments and nothing between a WAV and a transcript may depend on that — backend selection with a CUDA-to-CPU fallback that a `DecodeError` deliberately skips, the transcript renderer and the blank line it puts between entries — a single newline is a Markdown soft break, so the old form rendered as one unbroken paragraph, and `reflow_transcript` is the pure function `referat reflow` repairs the older files with — the `transcription` block of `meta.json`, the quality gate that decides whether the audio may be deleted and the `release_audio` that does the deleting — separable since step 15, because `referat promote --release-audio` is a person overruling that gate and `audio_released` has to mean the same thing either way. Calls out to diarization and then to identification, relabels the segments with whatever names came back, and regenerates the meetings dashboard once the meeting has been promoted. |
| [referat/merge.py](referat/merge.py)                   | Interleaving the two channels into one chronological list of `(start, label, text)` entries, with a fixed tie-break so simultaneous speech orders the same way every run. A segment's diarized speaker — a number, or a name, the owner's included — wins over its channel's label here; `ME` and `REMOTE` are what is left when nothing attributed a line. |
| [referat/diarize.py](referat/diarize.py)               | `pyannote.audio` over **both** channels — the microphone hears the whole room in a meeting held in person: who spoke when, aligned to the transcribed segments by overlap and renumbered `SPEAKER_01`, `SPEAKER_02`, ... across the meeting rather than per channel, so two channels cannot put two people behind one label. Harvests the clustering centroid per speaker and hands back the renaming map so the two stay together. Reports failure rather than raising, so a diarization problem never costs the transcript. Stubs `torchcodec` out before importing pyannote, which imports it eagerly, so Smart App Control has no unsigned DLL to block. |
| [referat/voices.py](referat/voices.py)                 | The known-voices database in `<meetings_dir>/.voices/`, or wherever `[paths].voices_dir` puts it: embeddings grouped by name, cosine matching of a diarized cluster against them under a threshold *and* a margin, the snippets cut for whoever is left over, and the owner bootstrap from a meeting whose microphone clustered into exactly one speaker. A lone name in the database is held to the margin on its own score, since there is no runner-up to beat. `speaker_channel` and `channel_speakers` answer which file a voice arrived in, which is what the labeling UI shows as a hint and what `referat relabel` gates on. Never raises into the pipeline. Biometric data — never synced, never sent anywhere. |
| [referat/label.py](referat/label.py)                   | `referat label`: plays an unnamed speaker's snippets, prompts for a name with fuzzy completion over the known ones, then writes the database, `meta.json` and the transcript's labels — the label field alone. `--forget` deletes a person and reverts them everywhere; both paths regenerate the meetings dashboard, since naming somebody is the only thing outside the pipeline that changes its Unnamed column. `run_json`, `run_apply` and `--forget --yes` are the same primitives without the prompt, for the VS Code extension's labeling panel — the prompt cannot be driven from a subprocess. `--forget` reverts every label a name covers to the lowest of them when diarization split that person across two clusters, which is a merge somebody already asserted by naming both. Needs no part of the `transcribe` extra. |
| [referat/rerun.py](referat/rerun.py)                   | `referat rerun`: transcribe a meeting again from the WAVs it kept. Refuses when there is no audio left or a live tray is already on the GPU, clears the previous run's speaker names and snippets because diarization renumbers from scratch, then hands the meeting to the pipeline. The only CLI command that needs the `transcribe` extra. |
| [referat/index.py](referat/index.py)                   | The meetings folder's own generated `INDEX.md` — one row per meeting with its title, duration, status, unnamed speakers and links to transcript and notes, newest first, with the staged meetings counted in a footer rather than linked. `meeting_title` reads the H1 of `notes.md` and is shared with step 13's digest; `status_words` prints the lifecycle as words for a rendered table, by a formatting rule rather than a second vocabulary. Rewritten at the end of every transcription, after `referat label`, and on demand by `referat index`; never raises, because a dashboard may not cost a transcript. A **different file** from this repository's `INDEX.md`. |

## VS Code extension — [referat-vscode/](referat-vscode/)

The primary UI, and with the tray icon the only graphical surface Referat has.
**It reimplements nothing**: every meeting it shows comes from `referat list
--json` and every change it makes is a `referat` verb, so the roots, the
formatters, the title rule, the lifecycle vocabulary, the name validators and the
voiceprint writes all stay in Python where they already exist once. A sidebar
webview since step 15, replacing step 11's TreeView, and packaged into an
installable `.vsix` at step 12 — nine files, of which one is code. F5 still runs
it from source, which is how it is developed.

| File                                                                              | Description                                                      |
| --------------------------------------------------------------------------------- | ---------------------------------------------------------------- |
| [referat-vscode/package.json](referat-vscode/package.json)                         | Manifest and contributions: the activity-bar container, the Meetings view — `"type": "webview"` since step 15 — the four view-title commands and the two settings. Everything per-meeting is a button inside the page and needs no command, no `contextValue` and no `when` clause, which is also how the `\b`-in-JSON footgun left this file. Activates on the view alone, so no window that never opens it spawns Python. Also the packaging half: `vscode:prepublish` bundles so a `.vsix` cannot be built around a stale `dist/`, and `repository` is what stops `vsce` stopping to ask about a missing one. |

| [referat-vscode/src/cli.ts](referat-vscode/src/cli.ts)                             | The one path to Python: `<repoRoot>\.venv\Scripts\python.exe -m referat.cli …` with `cwd` at the repository root, plus the JSON types — including the `MeetingStatus` union and the `projects` id-to-name map that lets a tag chip resolve without a second subprocess — and the failure messages — no venv, a non-zero exit, output that is not JSON. `mutate` is the one way a change is made: it hands back the CLI's own complaint, so a refusal reaches the user in the words of whatever owns the rule. | [referat-vscode/src/sidebar.ts](referat-vscode/src/sidebar.ts)                     | The Meetings webview view and its watcher, replacing step 11's tree. Sets `webview.html` **once** and thereafter posts documents, because re-rendering on every refresh would collapse an expanded row and stop a snippet mid-playback. Newest first, like the meetings `INDEX.md` and unlike `referat list` — a dashboard is read from the top. Watches both roots for `meta.json`, `notes.md` and `transcript.md`, debounced, because transcription rewrites `meta.json` several times a meeting and every refresh costs a subprocess. Turns snippet paths into webview URIs, which is why the meeting roots have to become `localResourceRoots` once Python has said where they are. |
| [referat-vscode/src/projects.ts](referat-vscode/src/projects.ts)                   | The tag picker and project CRUD, as native QuickPicks — VS Code already has a multi-select with a filter box, and a webview copy would be a worse one. Every path is a shell-out and every refusal is shown in the words the CLI used. |
| [referat-vscode/src/claude.ts](referat-vscode/src/claude.ts)                        | Finding `claude` and running `/cleanup` with it. Not on `PATH` on this machine, so it asks VS Code for the installed Claude Code extension and takes the binary inside it, resolved at spawn time and never cached — that path carries a version and changes with every update. Streams the last non-empty line of its output into the progress toast and the whole of it into the channel. Holds the `--allowedTools "Read,Write,Glob"` constant and the note that `Bash` may never join it. Never touches credentials. |
| [referat-vscode/media/sidebar.css](referat-vscode/media/sidebar.css)                | The sidebar's styling, entirely in VS Code theme variables so it follows the editor's theme. One rule per lifecycle value, and a value nobody styled still prints its own name rather than disappearing. |
| [referat-vscode/media/sidebar.js](referat-vscode/media/sidebar.js)                  | The page: render the posted listing grouped into collapsible sections by project — orphaned tag ids next, untagged last, a two-tag meeting under both — with a search box, keep the expanded rows and the filters across a refresh, remember the folded sections through `vscode.setState`, and post back what was clicked. Every node is built with `textContent` — a meeting title comes out of somebody's `notes.md` and a speaker's line out of a transcript, and neither is markup.
